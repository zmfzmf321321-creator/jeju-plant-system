# Gmail 자재 동기화

- Codex 로컬 예약 작업 `제주발전본부 자재 메일 동기화`가 매일 오전 7시(Asia/Seoul)에 실행됩니다. PC가 꺼져 있으면 다음 실행에서 아직 처리하지 않은 메일을 다시 찾습니다.
- 2026-10-03 14:16:28 UTC 이후 수신한 메일 중 실제 발신 주소가 `@komipo.co.kr`인 메일을 검사합니다. 이전 메일은 소급 반영하지 않습니다.
- 본문과 XLSX 첨부파일에서 제주발전본부 자재의 기력·내연·환경 자료를 찾습니다. 수량이 명확한 행만 처리하며, 현황표의 현재고를 자재관리의 현재고와 맞춥니다. 메일에 없는 품목은 그대로 둡니다.
- 메일의 `자재번호`는 `material_number`로, 별도 표기된 `품목코드`만 `item_code`로 보관합니다. 두 번호를 각각 비교하고, 번호가 없으면 대분류·품명·규격으로 비교합니다. 번호가 다른 품목을 가리키거나 후보가 여러 개면 검토 대상으로 남깁니다.
- `spec`에는 실제 규격만, `model_name`에는 실제 모델명만 저장합니다. 자재번호 전용 셀이나 `(자재번호)`가 붙은 값은 두 필드에 복사하지 않습니다. 별도 모델명이 확인되지 않으면 비워 둡니다.
- `private.inventory_mail_rows`는 메일·첨부파일·시트·행별 처리 결과를 보관합니다. `private.inventory_mail_messages`는 메일 단위 처리 상태를 보관합니다. 두 테이블은 공개 Data API에 노출되지 않습니다.
- `private.apply_inventory_mail_snapshot`은 신규 품목 등록과 수량 변경을 처리합니다. 기존 품목의 수량이 바뀌면 `inventory_movements`에 변경 전후 수량과 메일 출처를 남깁니다. 처리 완료 행은 재적용하지 않고, 검토 필요 행은 다음 실행에서 재시도합니다.
- XLSX 내장 사진은 이미지 앵커가 자재 행을 명확히 가리킬 때만 `private.apply_inventory_mail_photos`로 연결합니다. JPEG·PNG·WebP·GIF 형식과 품목당 활성 사진 5장 제한을 검사하고, 내용 해시로 중복을 막습니다. 연결이나 형식이 불명확한 사진은 검토 대상으로 보고합니다.
- 자동화의 매 실행 보고에서 신규·변경·동일·검토 필요 건수를 확인합니다. 첨부파일 접근이나 파싱에 실패한 메일은 재고를 변경하지 않고 다음 실행에서 재시도합니다.

예약 작업은 Codex 앱의 자동화 목록에서 일시중지하거나 수정할 수 있습니다. SQL 구조를 변경할 때는 `supabase/migrations/20261003141841_inventory_mail_sync.sql`부터 `20261006042602_inventory_mail_retry_review_rows.sql`까지의 동기화 마이그레이션을 순서대로 적용합니다.
